Course work for the CS-465 Full Stack Development I Course at SNHU.

## Reflection
1. Compare and contrast the types of frontend development you used in your full stack project, including Express HTML, JavaScript, and the single-page application (SPA).
  - In this project, we used two different front-end development approaches, including vanilla HTML, CSS, and JavaScript, where the server serves HTML pages to the user. CSS styles the pages, and JavaScript handles interactions. To improve this process, we used a library called Handlebars to make certain HTML elements easily reusable. This approach was viable and helped reduce the amount of dry code in the project. However, it still requires the server to constantly send pages depending on where the user navigates, and the CSS and JavaScript data remain unchanged by this improvement. This requires the user to wait for the page to load and puts more strain on the server. In contrast, the administrative SPA utilized a library called Angular, which takes a component-based approach to front-end development. Much like Handlebars, components allow certain HTML elements to be reused, but they improve on this concept by also housing all JavaScript and CSS logic and data. Rather than only the HTML aspect of the component being reusable, all logic about the element is also bundled with the component. Additionally, a component-based approach lets you swap components easily within the same page, so users can load all page components in one go, reducing server load. However, this increases initial load time, but it lets users navigate quickly between already loaded components on the site without waiting for a network request during navigation.
2. Why did the backend use a NoSQL MongoDB database?
  - The backend used a NoSQL MongoDB database because it simplified database integration. Rather than having to utilize tables and columns to organize data and to create specific queries to create, read, update, and delete data from these tables, the NoSQL database allowed the project to use JSON objects, which are native to JavaScript and other programming languages, and to perform queries using JavaScript syntax as well. Storing data as documents also made using retrieved data from the database easier, since the data was already parsed or formatted into a JSON object and no additional formatting or conversion was needed.
3. How is JSON different from Javascript and how does JSON tie together the frontend and backend development pieces?
  - JavaScript is a programming language that uses JSON, or JavaScript Object Notation, to store data within a single instance. Much like classes in programming languages that allow data and logic to be encapsulated in a single place, JSON does the same, except strictly with data. JSON allows the front end and back end to transfer data more easily by sending a single object rather than multiple variables, which can be time-consuming, especially when the needed variables change over time. Additionally, JSON makes data transfer easier and more consistent by converting the data into a string before transfer and parsing or formatting it upon receiving the data to ensure compatibility across programming languages.
4. Provide instances in the full stack process when you refactored code to improve functionality and efficiencies, and name the benefits that come from reusable user interface (UI) components.
  - Refactoring was a major part of the development process, as reworking code to make it more efficient and easier to manage helped optimize the project. The main instance of this refactoring was in the HTML customer pages, as most of the HTML pages used repeated elements and defined the same group of elements in multiple places across the various pages. Updating or changing any of these repeated elements would have required changing them in all places, which could result in errors. Thus, switching to Handlebars templates allowed these duplicate elements to be removed and replaced with a call to the template, isolating the code in a single place. This change proved necessary when updating the links in the navigation bar, as only the navigation bar template needed to be changed to reflect across all pages. Refactoring the project, specifically the front end customer-facing portion, to use Handlebars templates made managing the project much easier and allowed for elements to be easily changed and reused as needed.
5. Methods for request and retrieval necessitate various types of API testing of endpoints, in addition to the difficulties of testing with added layers of security. Explain your understanding of methods, endpoints, and security in a full stack application.
  - For this project, a RESTful API was created that allows the creation, reading, updating, and deleting of trip packages by navigating to specific endpoints and using the appropriate HTTP Request method to perform the required action. This process works by attaching specific programming methods to the endpoints, and by navigating to them, users can trigger those methods. For instance, navigating to the '/api/trips' endpoint and making a POST request will allow a user to trigger the trip creation method, while a GET request would trigger the method for reading and receiving all trips from the database. This approach allows any user to attempt to access the necessary methods for interacting with the database without directly exposing the database to the public. Still, to ensure that only authorized individuals can access the database, security was needed to ensure that only specific individuals can trigger the methods when navigating to the endpoints. To accomplish this, JSON Web Tokens were used to encrypt user accounts into a safe-to-store string that can be sent with the HTTP request made to the restricted endpoints. After validating the token, the user could trigger the method, making it usable only for authorized individuals.
